## Freshness and publishing

- `release_fingerprint` covers serialized project/configuration, selected index, full scenario and verification/protocol snapshots, actual source plan/section and attachment SHA-256 values, template/manifest/image bytes and the regulation registry. Identical input produces identical fingerprints. Engineering snapshots omit release metadata and include source PDF hashes, so title edits keep a valid engineering calculation and replacement plan bytes make it stale.
- Widget traces and geometry edit handlers invalidate the preview immediately. A published preview polls for out-of-process file changes every 1.5 seconds. Both the report tab and open preview display the stale label.
- Preview and save rebuild context/bundle, binding, drawing/appendix plan, register and physical contents from current input. A mismatched verification index or obsolete calculation is rejected. A forbidden requested status is rejected on save. Preview explicitly recompiles as preliminary if the requested status is forbidden. Effective status is printed on the title.
- Local staging is on the destination filesystem. Save renders the PDF, stages project/protocol/source files, checks the live fingerprint, installs sidecars with rollback backups, rechecks the live fingerprint immediately before replacing the final PDF, and removes staging. A source edit, failed protocol write or failed replace leaves the prior PDF intact. Existing sidecars are restored if installation fails. The output cannot alias a selected input PDF.
- Minimal integration changes outside the app/state helper expose the existing merger preflight, render identified pending graphical leaves through the existing sheet planner and print the effective status in the title's reserved space. Drafts retain explicit physical leaves for absent danger-zone evidence, absent SOZR, incomplete legacy tie rows and sheets which cannot fit the accepted format. Coordination, approval and production remain blocked for these issues. No alternate engineering values or scale are calculated.

## Self-review and limitations

Rechecked the composer matrix, asset bytes, selected index and binding, preflight/merge consistency, page-map integrity, legacy report signatures, template conflict persistence, source-copy destinations and worksheet/control layout. Status advancement is explicit. Revision files are created only on a user save. The PDF is atomically replaced; rollback covers ordinary Python/filesystem exceptions during sidecar installation. A machine crash during a multi-file installation is outside this transaction guarantee. Full hashing, local PDF inspection and rendering run on the GUI thread and may take time on large inputs. Original external attachments retain their local paths, so moving/removing them produces a visible missing/pending condition on the next check. The test process used only local synthetic fixtures.
