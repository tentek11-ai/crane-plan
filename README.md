# КранПлан

Исследовательский проект по автоматизации проектирования размещения башенных кранов на строительной площадке.

## Текущий этап

- Версия интерфейса, расчётного ядра и переносимой сборки: `2.2.2`.
- Этап: работоспособная автономная версия для Windows с независимой проверкой однокрановых вариантов.
- Реализованы PDF-подложки плана и разреза, обрезка и приглушение фона, масштабирование с сохранением координат разметки, контур здания на разрезе, подбор пятиметровых секций и уровней пристёжек, баланс активных подъёмов, нормативные проверки, подбор до двух кранов, сравнение вариантов и PDF-отчёт.
- Разделы «Каталог кранов» и «Нормативные документы» используют автономную локальную библиотеку. Краны можно добавлять вручную; пользовательские характеристики участвуют в подборе только с обязательной экспертной проверкой.
- Переносимая сборка формируется в `10_exports/releases/CranePlan_Portable_2.2.2`.

## Куда положить первые материалы

- Основные научные статьи: `01_sources/01_core_articles/`
- Оригиналы ППРк: `01_sources/03_pprk/01_original/`

Оригинальные исходные файлы не изменяются и не перезаписываются. Из-за размера и возможной чувствительности они не включаются в Git; целостность ключевых файлов фиксируется контрольными суммами SHA-256 в реестрах.

## Принципы проекта

- Распознавание, инженерный расчет и подбор реального оборудования разделяются.
- Расчеты в реальных единицах выполняются только после калибровки масштаба.
- Неизвестные данные отмечаются как `UNKNOWN` или `REQUIRED INPUT`.
- Все инженерные результаты требуют проверки специалистом.
- Значимые эксперименты должны быть воспроизводимыми.
- Validation-ППРк не используются для настройки метода до независимой проверки.

## Запуск исходной версии

`Запустить КранПлан.bat`

Для передачи пользователю применяется переносимая сборка: вся папка копируется целиком, установка не требуется.

Версии библиотек, с которыми проверена сборка, закреплены в `requirements-lock.txt`.

## Расчётное ядро 2.1

Точка входа для разработчика — `crane_plan.engine.run_engine_v21`. Запрос содержит модель проекта схемы 3, прослеживаемый каталог, явно заданные координаты кандидатов и, при наличии, предлагаемое решение. Сервис:

- детерминированно проверяет каждую операцию по вылету, грузоподъёмности, высоте, маршруту, опасной зоне и положению основания;
- между паспортными вылетами принимает грузоподъёмность следующей большей точки таблицы без линейной интерполяции;
- независимо перепроверяет предложенное решение, не используя результат первичного оценщика;
- выдаёт измеренные значения, пределы и стабильные коды причин;
- создаёт канонический протокол JSON с версиями, источниками и SHA-256 входа и результата.

Минимальный импорт:

```python
from crane_plan.engine import EngineRequestV21, run_engine_v21

result = run_engine_v21(EngineRequestV21(
    project=project_v3,
    catalog=crane_configurations_v3,
    candidate_coordinates=((x_m, y_m),),
    proposed_solution=solution_v3,
    run_id="calculation-001",
    created_at="2026-10-20T10:00:00+03:00",
))
```

## Проверка и выпуск варианта в интерфейсе

Рабочая последовательность: текущий оптимизатор находит до трёх вариантов → ядро 2.1 независимо проверяет каждый вариант → пользователь выбирает один вариант → программа разрешает или блокирует выпуск предварительного ППРк.

Статусы независимой проверки:

- `VERIFIED` — вариант проверен и может быть выпущен;
- `VERIFIED_WITH_CONDITIONS` — выпуск разрешён, условия печатаются в отчёте;
- `EXPERT_REVIEW_REQUIRED` — просмотр разрешён с отметкой «Не для выпуска», итоговый PDF блокируется;
- `REJECTED` — вариант не выполнил обязательное ограничение, итоговый PDF блокируется.

Перед подтверждением варианта пользователь должен отметить, что массы грузов, оснастка и принятое значение высоты строповки сверены с проектными документами. Изменение или удаление груза автоматически снимает подтверждение и очищает устаревшие результаты.

Для выпущенного варианта рядом с PDF сохраняется `reports/calculation_protocol_v21.json` с источниками, измеренными значениями, кодами причин и SHA-256 входа/результата.

Ограничения этапа 2.1: ядро не выполняет собственный поиск координат, Парето-ранжирование или календарное планирование. Независимой проверкой охватывается один кран `Liebherr 130 EC-B 6`; двухкрановые варианты, пристёжки, неоднозначное назначение нескольких складов и краны без записи V3 требуют экспертной проверки. Эти функции относятся к следующим этапам 2.2–3.0.

Проверка 20.10.2026 на Python 3.12.14:

```powershell
$env:PYTHONPATH=(Resolve-Path '.\05_src').Path
python -m unittest discover -s 06_tests -p "test_engine_*.py" -v
python -m unittest discover -s 06_tests -v
```

Автоматические тесты GUI проверяют оркестрацию без запуска `mainloop`; переносимая Windows-сборка требует отдельной ручной приёмки перед публикацией.
